# 卷积—池化片上融合

本实现将卷积后处理的 INT8（8位整数）结果直接送入可配置 MaxPool（最大池化），省去卷积中间特征图写回 DDR（Double Data Rate，双倍数据速率外存）后再读入池化的过程。独立卷积、最大池化及全局平均池化路径保留。窗口高宽、纵横步长由软件逐层指定，不再固定为2。

流式融合当前保持 VALID（不补边）语义；独立最大池化已支持四侧补边，带补边层由编译器保留独立任务。状态机、字段和验证见 [最大池化补边](maxpool_padding.md)。此前遗漏的融合引擎窗口/步长接线已补齐并通过3×3、步长2的整机对照。

显式全连接形状转换也可复用本池化引擎。其GEMM输出通过坐标转换器进入池化，参数头、补齐行过滤和容量边界见[全连接池化融合](fc_pool_fusion.md)；卷积仍保留原坐标语义与通道分块调度。

## 数据路径与所有权

原始输入缓存与独立窗口接口的结构、端口和最新验证见[原始池化输入缓存](pooling_input_buffer.md)。

```text
普通路径：C SRAM / PSUM → Bias/Requant/ReLU → 结果双缓冲 → DMA → DDR → Pool
融合路径：C SRAM / PSUM → Bias/Requant/ReLU → 结果消费者 → 原始输入行缓冲 → 窗口读取 → MaxPool → 输出FIFO → DMA → DDR
```

普通 K 分块路径复用 `result_tile_buffer`，两个 bank 保存后处理结果以及该计算块的空间、通道起点。融合消费者按行同步读取，使用 valid/ready 向 `stream_maxpool2x2` 传递一个空间位置的 COLS 路 INT8。

容量足够时沿用原调度。全部通道的池化状态放不下、但一个 COLS 通道块能放下时，自动改为按通道块处理：完成这一组通道的全部空间位置，再处理下一组。描述符仍然是一条融合命令，N、权重/参数地址和最终 HWC 张量布局保持原有含义。

多 K A 复用使用原 PSUM 槽；只在最终 K 块累加完成后读取并后处理，再交给同一个池化消费者。其调度器在消费者完成前保持 PSUM 槽和量化参数有效。

池化保存最近 KH 行的原始 INT8 输入，而不保存整幅特征图或提前归约为部分最大值。这里的原始数据是 Bias/Requant/ReLU 之后、池化计算之前的数据。每四个通道组成一个32位字，输入位置写入环形行缓冲的索引为：

```text
((input_row % kernel_height) * input_width + input_col)
    * (channels / 4) + channel_base / 4 + group
```

按通道块处理时，环形地址改用块内通道组号：

```text
((input_row % kernel_height) * input_width + input_col)
    * (COLS / 4) + group
```

外存输出地址仍使用完整的 `channels` 和全局 `channel_base`。同一批缓存位置在一个通道块全部处理完后复用，卷积中间结果不写入 DDR。

窗口右下角输入完成保存后，窗口读取端逐个取出 KH×KW 个原始样本，再由最大值运算模块完成有符号 INT8 归约。缓冲和窗口读取保留完整样本，后续池化种类可以复用相同入口；本次仍只实现最大池化。步长间隙和尾部像素仍参与输入握手和原始行写入，但不触发窗口输出。原 Bias、量化、ReLU 顺序不变。每个通道块的空间位置必须按光栅顺序到达。容量足够时，不同通道块可以交错，兼容原 M→N、N→M 和多 K A 复用输出顺序；按通道块处理时，遍历为 N→M→K，即每个 N tile 的全部 M/K 完成后才换下一组通道。窗口全部读取完成前暂停接收后续输入，避免环形行覆盖仍在读取的样本。新任务的首个窗口会先写齐自己的输入，因此任务开始和切换通道块时不需要清空整块存储。

结果 bank 在该计算块的全部有效行成功复制进原始池化行缓冲后释放，不再等待该块相关的 AXI 写响应。多 K A 复用的 PSUM 槽和参数同样在最终后处理行全部交接后退休。整层完成仍等待全部计算块提交，以及窗口回放、归约结果、输出 FIFO 和在途写响应排空。下游停顿时结果和坐标保持稳定；尚不完整的窗口输入保留在原始行缓冲。

`pool_result_dma` 在结果握手时将绝对目标地址和32位数据存入 FIFO，DMA 将队头复制进活动写寄存器后释放对应队列位置。FIFO 默认16项，通过顶层 `POOL_OUTPUT_FIFO_DEPTH` 配置，支持1及非二次幂。当前每个结果字仍发一条单拍 AXI 写请求，计算可在队列有容量时继续；本次没有增加 burst 合并或多在途写事务。运行 `make pool-fifo-check` 验证。

## 描述符与支持范围

- opcode 仍为 Conv（2），flags bit7 为 `FUSE_MAXPOOL`，即描述符第 0 个 word 的 bit15。原 flags=7 的 Conv 首 word 从 `0x0702` 变为 `0x8702`。
- M、N、K 及卷积几何继续描述未池化的卷积输出；C_BASE 直接指向池化后的最终 HWC 张量。融合后不再追加原独立 Pool 描述符。
- 第15个字（从0计数）的四个字节依次是窗口高、窗口宽、纵向步长、横向步长，即 `{stride_w, stride_h, kernel_w, kernel_h}`。每项为1～255的整数，支持非二次幂、横纵不同步长及步长大于窗口。整个字为0时兼容旧2×2/步长2；非零字中的任一字段为0均非法。普通卷积、矩阵乘、残差加和全局平均池化要求此字为0。
- 使用 VALID（不补边）最大池化：`OH=floor((H-KH)/SH)+1`，`OW=floor((W-KW)/SW)+1`。输入高宽至少为对应窗口尺寸，允许奇数输入和未被末尾窗口覆盖的像素。需要开启 INT8 重定量；M/N 继续满足原 ROWS/COLS 的完整计算块限制。此修改只调整池化步长，卷积自身的原步长支持范围不变。
- COLS 至少为 4 且为 4 的倍数，通道数是 4 的倍数且能被 COLS 整除，写接口为 32 位。输出基址四字节对齐。
- 顶层参数 `POOL_LINE_WORDS=1024`，对应4 KiB的逻辑行存储。全部通道原始行需求为 `full_words=KH*input_W*(channels/4)`，一个通道块需求为 `tile_words=KH*input_W*(COLS/4)`。容量与池化步长无关。`full_words` 能放下时使用原模式；仅 `tile_words` 能放下时使用通道分块模式。FC 和卷积共用这套原始输入缓冲；FC 仍要求 `full_words` 能放下。
- 不满足硬件约束的融合描述符在执行前报错，不写结果。编译器融合优化自动保留原两条独立任务及原窗口/步长配置，独立池化从外存按窗口读取，不受该行缓冲容量限制。下一次合法启动可恢复。

## 缓冲用满时的处理

1. **暂时占满**：窗口回放期间本地输入暂停；DDR 停顿先由输出 FIFO 吸收，FIFO 满后经归约器和窗口接口逐级反压，上游保持数据及坐标。源结果 bank 或部分和槽在其全部有效行交接后释放；两个源结果分区都占用时，仍会暂停新的结果采集。整层结束前收完全部写响应，不覆盖尚未消费的数据。
2. **全部通道状态放不下**：自动一次只保留 COLS 个通道的 KH 行原始输入，按通道块完成卷积与池化，再复用行缓冲处理下一块。结果写入原完整输出张量中的对应通道位置，卷积中间张量仍不落 DDR。该模式保持一个层描述符，通过改变计算遍历顺序实现。
3. **一个最小通道块也放不下**：等待和通道分块均不能解决。软件才选择卷积写外存、独立池化读外存的回退路径；硬件拦截误发的超限融合命令。当前不在计算途中动态溢出原始行缓存到外存，也不实现宽度方向分块。

例如输入宽128、64通道、2×2窗口：无论步长为1还是2，全通道原始行都需要 `2*128*16=4096` 个字，超过默认4 KiB。默认 COLS=4 的单块只需 `2*128*1=256` 个字，因此仍可融合，分16个通道块依次处理。所有合法配置保持原计算语义，不通过改变步长来迁就缓存。

代价是输入特征可能随不同输出通道块重复读取，且该模式不采用跨 N 块的多 K A 复用。因此减少了卷积中间结果写入和池化输入读取，并不保证每层周期都减少；需要比较新增输入读取与省去的中间数据流量。原本容量足够的路径不改变遍历顺序。

## 运行

```bash
# 单元、系统对照、非二次幂宽度、多lane和跨行tile
make fusion-check

# 现有四张 MNIST 图，原五描述符与融合三描述符分别验证
make mnist-all
make mnist-fused
```

`mnist-fused` 在 testbench 中读取原部署镜像后，将两对 Conv/Pool 改成三条描述符，不修改 `artifacts/npu`。它检查 Pool1、Pool2、FC 的逐字节黄金结果、分类结果，以及两个卷积中间区域没有外存读写且保持初值。

原模型编译工具增加可选的 `--fuse-conv-pool`，默认关闭。融合 pass 检查相邻算子、唯一消费者、几何和最小通道块容量，并避免池化输出提前覆盖卷积仍需读取的输入、权重或参数。报告记录 `channel_tiled`、`pool_full_line_words`、`pool_active_line_words` 和 `pool_channel_block_channels`，区分全量需求与实际活跃状态。部署文件保留中间区域的地址分配和软件 golden，但不要求融合硬件在这些区域写入卷积结果。见 [编译器说明](../compiler/README.md)。

纯描述符/容量策略回归可运行 `python compiler/test_pool_channel_tiling.py`。它直接读取生产函数和现有单测方法，兼容只有 Python 2、没有 NumPy 的环境；不替代完整 Python 3/NumPy 模型编译及 RTL 数值验证。TFLite ResNet-8 入口当前不提供 MaxPool 或卷积池化融合，因此本次没有扩展该入口的算子范围。

以下性能、容量和日志对应保存部分最大值的旧版本，不代表原始输入行缓冲版本。新版本采用更大的原始行容量公式并增加窗口读取，其周期和流量需重新测量。

### 2026-10-23：行缓冲容量不足时的通道分块

整机对照使用4×4阵列、卷积输出4×8×12、3×3卷积、8个输入通道，
K=72；测试将K块大小设为32，覆盖32+32+8的部分和累加。外存模型对
读地址、读数据、写地址、写数据和写响应分别施加确定性停顿。两条独立
Conv/Pool命令与一条融合命令使用相同输入、权重、量化及存储时序，所有
输出逐字节对照软件黄金值。以下为普通多K、不启用ReLU的结果：

| 池化配置 / 行缓冲 | 独立执行周期 | 通道分块融合周期 | DDR写入字节 | 全部AXI64读拍 |
|---|---:|---:|---:|---:|
| 2×2、步长2；4个字 | 8,760 | 7,062 | 480 → 96 | 1,101 → 989 |
| 2×2、步长1；14个字，写响应延迟30周期 | 12,901 | 7,196 | 636 → 252 | 1,257 → 989 |

第一例全部通道需12个字，但只有4个字（16字节）可用；分三次分别处理
通道0～3、4～7、8～11，每次完成全部空间位置并复用同一片存储。原来
容量不足会回退为独立执行，现在保留融合：384字节卷积中间写入和384字节
池化逻辑读取均为0，实际只写96字节最终池化结果，周期减少约19.4%。
重叠窗口例全通道需要42个字，单块需要14个字，省去384字节中间写入和
1,008字节池化窗口逻辑读取。读拍统计还包含描述符、权重和量化参数，
不能将读拍差等同于池化逻辑读取量。

这些小输入可由原输入缓存容纳。另将输入缓存缩小到2个64位字，检查
频繁替换下的相同几何。普通多K仍从15,284降至13,614周期；但原来开启
多K A复用的逐通道量化场景，分块后读拍由1,394升至1,794，周期由11,513
升至13,978。虽然写入仍由480降至96字节，全部读数据与写入字节之和却
由11,632升至14,448。因此，消除中间张量搬运并不等于总外存流量下降，
也不能直接换算成功耗收益。压力测试见
`build/vcs/conv_pool_fused_npu_tb/channel-tiling-cache-pressure/simulation.log`。

应报告总读拍和总周期，而非仅报告省去的池化流量。融合仍由软件可选
优化开关控制，当前容量策略没有根据输入缓存命中情况自动择优；有明显
输入重复读取代价的层可以保留独立执行。当前按最小COLS通道块执行，
没有进一步将可容纳的多个通道块合并为一个调度组。

本次通过29个功能testbench回归、融合检查、COLS=4/8/12池化单元测试，
覆盖恰好最小容量、全负数、重叠窗口、跨行计算块、步长间隙、通道切换、

分类及周期与下表原结果一致。编译器23项描述符/容量策略测试通过，

### 原容量足够场景

2026-10-22，VCS O-2018.09-SP2，同一默认阵列和同一 MNIST 外存模型：

| 每图指标 | 原 Conv/Pool 独立执行 | 两对 Conv/Pool 融合 |
|---|---:|---:|
| 描述符数 | 5 | 3 |
| 总周期 | 68,542 | 51,312 |
| 外部读事务 AR | 3,994 | 1,610 |
| 外部读数据拍，64 位 | 16,454 | 14,070 |
| 外部写事务 AW | 2,952 | 600 |
| 外部写数据拍，32 位 | 2,988 | 636 |
| 实际写入字节 | 11,952 | 2,544 |

四图分类仍为 7、2、1、0，Pool1/Pool2/FC 黄金结果全部一致。周期减少约 25.1%，为这个具体模型和仿真存储时序下的结果，不代表任意网络的加速比，也不是频率、功耗或面积签核。

被消除的 Conv1/Conv2 中间张量合计 9,408 字节，因此分别避免 9,408 字节逻辑写回和 9,408 字节池化逻辑读取。外部 AXI64 的实际读拍还受到原 AXI32 读取适配和描述符数量影响，不能直接将读拍差当作中间张量大小。

系统对照还覆盖带 AXI（Advanced eXtensible Interface，高级可扩展接口）全通道停顿的普通多 K、逐通道量化/ReLU 的多 K A 复用、B 驻留、宽度6、ROWS=3跨行、COLS=8，以及步长1重叠窗口、3×3窗口、横纵不同步长、步长3/5间隙和容量不足回退。额外将写响应延迟设为200周期，两个结果分区同时保存有效数据累计24,365周期，全部输出正确且任务可完成，日志为 `build/runtime-full-buffer.log`。池化单元另覆盖COLS=4/8/12、字段255边界、恰好容量、连续任务、非法配置及恢复。独立池化与融合均使用同一输出几何。
