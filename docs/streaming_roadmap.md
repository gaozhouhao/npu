# 从当前 NPU 到层间流式结构

核对日期：2026-10-25。本页依据当前工作区 RTL 和编译器说明已有能力及后续设计。池化输出 FIFO 与独立 DMA 已实现；通用层间路由、片上 Conv 输入和跨层调度仍待完成。

当前已经实现 **tile 内计算/搬运重叠，以及 Conv/FC → 后处理 → MaxPool 的局部流式融合**。通用层间流水还需要层间接口、片上特征图入口、路由和跨层调度。给每个算子放两个缓存，并不能单独完成这些工作。

## 怎样理解“层”和“流水级”

Conv、FC、Pool、ReLU 是网络里的逻辑算子，硬件不必为每个算子各配一个独立引擎和一份完整特征图缓存。当前 Conv 和 FC 复用同一套 GEMM 阵列；Bias、Requant、ReLU 已放在 `gemm_postprocess` 中。ReLU 可以与生产结果的后处理一起完成，后面有 Pool 时直接交给 Pool。

层间存储更准确地称为显式管理的 buffer。按算子的消费方式选择：

| 数据关系 | 合适的起点 | 要解决的问题 |
| --- | --- | --- |
| 逐元素、生产与消费顺序相同 | 寄存器或 FIFO | 少量速率波动、背压 |
| 以完整 tile 交接 | tile 双 bank | 一块生产、一块消费，明确所有权与释放条件 |
| Conv/Pool 的滑动窗口 | 行缓冲、窗口缓冲 | 邻域依赖、重叠数据复用、边界补零或忽略 |
| tile/channel 顺序不一致 | 可寻址 SRAM 与必要的重排 | 数据齐备条件、bank 冲突、输出顺序 |
| 残差分支或多个消费者 | 保留数据的 buffer | 各消费者完成前不能覆盖，需要跟踪生命周期 |

双缓冲是一种实现手段，不是每层必须具备的结构。以整张特征图为单位交换双缓冲时，消费者仍要等待整图就绪；想让同一张图的前后层重叠，需要按行、条带或 tile 提前交接，并满足窗口与通道归约依赖。

## 当前实际数据通路

```text
DDR 输入/权重
      ↓
A/B 操作数双 bank ── 预取下一 tile
      ↓
单套 GEMM 阵列（Conv / FC 共用）
      ↓
Bias / Requant / ReLU
      ↓
结果交接（普通路径：tile 双 bank；多 K A 复用：PSUM 结果）
      ├── 普通模式 → result_write_dma → DDR
      └── 融合模式 → 坐标适配 → 原始池化行缓冲
                                  ↓
                              MaxPool → 输出 FIFO → DMA → DDR
```

融合链内用 `valid/ready` 和空间/通道坐标交接结果。全连接的显式 HWC 形状转换由 `pool_coordinate_mapper` 完成，过滤物理补齐的样本行。这里主要是坐标解释，不是通用张量转置器。

| 能力 | 当前证据 | 现有边界 |
| --- | --- | --- |
| 操作数预取与计算重叠 | `operand_bank_controller`、`gemm_tile_scheduler` | 属于同一层内的 tile 调度 |
| 计算结果与消费者解耦 | `result_tile_buffer` 的两个 bank | 只存本地结果 tile，不是通用层间特征图存储 |
| Conv/FC 后处理后直接池化 | `npu_gemm_engine` 的融合消费者 | 支持范围受布局、VALID 池化、通道与容量约束限制 |
| 原始窗口数据片上复用 | `pool_window_buffer` → `pool_max_reducer` | 窗口回放期间暂停接收新输入 |
| 不接 Pool 时写 DDR | `fuse_maxpool_q` 选择结果 DMA 或融合消费者 | 固定的两条路径；池化结果仍写 DDR |
| 顺序多层执行 | `npu_command_reader` 的 `ST_WAIT_EXEC` | 当前层完成后才取下一条描述符 |

## 还差哪些关键能力

### 1. 可复用的层间流接口与出口

现有融合接口已经有 `valid/ready`，可以作为起点，但需要把数据与元数据约定推广到其他算子。至少明确数据位宽、有效 lane、空间/通道位置、tile/frame 边界、布局、量化参数归属，以及遇到背压时保持哪些信号。

池化结果已通过内部 valid/ready 接口进入 `pool_result_dma` 的输出 FIFO，再由独立 AXI writer 写 DDR。后续应将这条结果流推广到公共接口，再由出口选择送到下一算子或 DDR。支持一份数据同时送两处时，每个消费者都必须完成接收后才能释放；普通二选一不能代替分叉。

当前模式在命令开始时确定。后续路由切换应在规定边界执行，等待相关队列和在途事务排空；不应在一个 tile 或 AXI 事务中途直接切换所有权。

### 2. 下一层 Conv/FC 的片上输入路径

`operand_fetch` 和 `conv_patch_reader` 现在从 AXI 取输入，Pool 的输出没有接回下一条 Conv/FC 的输入。

需要增加 feature buffer 到操作数装载/窗口生成的片上读取入口，明确可读数据范围、读写端口、bank 所有权、halo 和边界处理。后一层卷积只有在所需窗口和输入通道数据齐备后才能形成最终输出；FC 的每个输出也要完成整个 K 维归约。可以边到达边累加，但不能把尚未完成归约的部分和当作最终激活送出。

当前卷积池化在缓冲不足时可能按通道块扫完整张图。这适合复用小行缓冲，却可能与后一层卷积要求的空间/全通道顺序冲突。因此先选择兼容的 tile 遍历顺序，再决定是否增加重排存储。更改坐标含义解决不了真正的数据到达顺序冲突。

### 3. 允许按 tile/条带推进的调度与资源分配

`npu_command_reader` 接受一条命令后等待完整 `exec_done`，随后才前进。当前顶层也按活动引擎选择 Pool/ADD/GEMM 的读写通路，缺少多层同时活跃时的队列、依赖跟踪和事务所有权管理。

调度需要区分“输入可用”“当前 tile 可计算”“输出已交接”“整层排空”等事件，并保存并发阶段的独立配置。只有去掉整层等待，不会自动补齐这些依赖。

另外，当前只有一套 Conv/FC 阵列：

- 希望 **Conv1 与 Conv2 同时计算**：需要增加独立阵列，或将足够的计算资源划分给两层。
- 希望 **保留单阵列、减少 DDR 中间搬运**：可以按 tile 切换层配置，配合片上特征存储与 PSUM。这仍有价值，但两层的阵列计算时间需要相加，还要计入切换代价。
- 希望 **Conv、Pool、写回重叠**：现有独立运算与搬运模块已经提供基础，应优先完善这一段。

### 4. 让缓冲真正隔离短时停顿

池化计算结果现在先进入输出 FIFO，每项保存绝对目标地址和32位结果。独立 DMA 将队头复制到活动写寄存器，再按 AW → W → B 完成单字写回。writer 忙不再直接关闭池化输入；FIFO 满后经 reducer 和窗口接口逐级反压。窗口回放期间仍暂停接收原始输入。

融合 feeder 逐行 READ → CAPTURE → SEND，最后有效行握手后释放源 tile，不再逐 tile 等待写响应。普通快照 bank、多 K A 复用的 PSUM 与参数在数据全部交接后可退休；整层完成继续等待池化、FIFO 和全部写响应排空。默认 FIFO 深度16，可用 `POOL_OUTPUT_FIFO_DEPTH` 调整，支持1及非二次幂。

这解决有限写延迟下的生产/消费解耦，不改变 DDR 的长期服务能力。当前仍为每个32位结果一条单拍写请求；连续输出可在后续合并 burst，但需处理地址连续性、尾字节、通道块间的跨度与 AXI 边界。

### 5. 编译器生成流式分组与回退计划

通用图后端 `graph_compiler.py` 已融合满足条件的 ReLU，但其余节点仍生成独立层描述符，并为激活分配完整 DDR 区域。原 SmallCNN 入口有可选 Conv/Pool 融合，FC/Pool 则有显式构造工具；这些能力还没有形成通用的跨层流式计划。

后续需要由软件检查唯一/多个消费者、数据布局与量化兼容、tile 顺序、片上容量及资源占用，生成流式分组和数据出口配置。不满足条件时保留 DDR 路径。残差、分叉以及不能驻留的中间状态，均需纳入张量生命周期，而不是简单跳过后一层。

## 建议实施顺序与验收

| 步骤 | 具体交付 | 验收条件 |
| --- | --- | --- |
| 1（已实现） | Pool 内部结果流 + 输出 FIFO + 独立 DMA | 同一 Conv/FC→Pool 数值不变；长时间写背压无丢失、重复、覆盖；源 tile 交接与整层写完分别完成 |
| 2 | 层间流约定和出口选择，保留普通写 DDR 路径 | 同一算子结果经流出口与 DDR 出口的数据逐字节一致；在规定边界切换；排空后再报完成 |
| 3 | feature buffer 及下一 Conv/FC 的片上读入口 | 选定的小网络中间张量区域无 DDR 读写；检查窗口、通道归约、尾块与量化 |
| 4 | tile/条带依赖调度和配置上下文 | 覆盖单阵列分时执行；有独立资源时再验证真正跨层并发；所有数据依赖均满足 |
| 5 | 图编译器自动分组、容量检查和 DDR 回退 | 同图流式/独立路径一致，分叉数据生命周期正确，不可融合配置可回退 |

第一步已接入现有融合链，运行 `make pool-fifo-check` 验证。后续每步保留独立执行对照，压力测试覆盖上游断流、下游停顿、满/空 bank、跨窗口、末尾有效 lane、连续任务和错误恢复。测试应核对数值、握手计数和 DDR 地址访问，性能同时报告周期、总读写字节和计算停顿。

## 哪些延时可以隐藏

对能够独立并发、以相同工作块计量的阶段，稳态每块时间趋近最慢阶段的服务时间，首次填充与最终排空仍有开销。FIFO 和双 bank 可以吸收短时波动；若 DDR 或某个算子的长期服务速率低于生产速率，缓冲最终会满并反压上游。共享同一阵列的两层不能套用独立阶段的吞吐公式。

因此，流式结构的收益来自减少中间张量搬运、复用窗口数据、让独立阶段重叠，以及匹配阶段吞吐。是否更快，要看具体网络、调度顺序和内存时序。当前已有输入重读导致融合变慢的实际例子，见[卷积池化融合](conv_pool_fusion.md)。

现有约束见[架构说明](architecture.md)、[原始池化缓存](pooling_input_buffer.md)、[FC 池化融合](fc_pool_fusion.md)。本页描述的通用路由、片上 Conv 输入与跨层调度尚未加入 RTL；已有回归通过只能证明现有能力。
