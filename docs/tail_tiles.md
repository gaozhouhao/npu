# 通用计算尾块

GEMM 和卷积的描述符继续保存逻辑 M、N、K，不把它们改成物理补齐尺寸。调度器按向上取整的块数执行，阵列仍处理完整的 ROWS×COLS 物理块。

```text
valid_rows = min(ROWS, M - m_tile * ROWS)
valid_cols = min(COLS, N - n_tile * COLS)
last_k_size = K % K_TILE_SIZE，整除时使用完整 K_TILE_SIZE
```

尾块可以只缺行、只缺列、只缺 K，或同时在多个方向不完整。逻辑尺寸小于一个块的情况也采用同样规则。所有向上取整加法先扩展到64位，并在截断为 TILE_COUNT_WIDTH 前检查块计数范围。

## 读取与计算

普通矩阵 A 只读取有效行，转置权重 B 只读取有效输出通道；缺少的 lane 在本地操作数缓存中补零，不发起对应的外存读取。每条真实 K 行仍保留按8字节对齐的物理跨度，末个读取拍可以包含行内 padding。卷积读取器已有空间越界判断，尾部位置填输入量化零点；未量化任务使用数值0。

偏置及逐通道量化参数只读取 `valid_cols` 项，未使用 lane 的参数清零。因此新的逻辑 N 命令不要求额外分配无效权重行或参数记录，但区域末尾仍须允许最后一个64位读取拍覆盖对齐填充字节。已有 FC 工具显式补齐 M/N 的方式继续兼容；描述符使用物理尺寸时，这些补齐位置仍被视为该命令的有效输出，由调用者按原方式裁剪。

K 方向继续使用现有累加机制。只有最终结果经过后处理进入结果消费者。未使用的物理行列可以参与内部计算，但不会产生对应的外存写入。

## 结果元数据与写回

结果双缓冲在捕获时锁存有效行列数，并与地址、空间和通道坐标一起保留到消费完成。PSUM 路径在写响应完成前保留计算块及其有效尺寸。

`result_write_dma` 接收 `tile_valid_rows`、`tile_valid_cols`。每行只写真实列对应的字节，只处理有效行；零尺寸或超过阵列范围的元数据报错且不读结果缓存、不发写请求。

INT8 尾列可能落在32位字的中间。DMA 把 AXI 地址向下对齐，按原始行地址偏移生成 WDATA 和 WSTRB，保护同一物理字内相邻行或张量的数据。AW、W 受反压时地址、数据及掩码保持稳定。每个 burst 不超过256拍且不跨4KiB边界，所有写响应结束后才报告完成。

卷积输出仍为紧凑 HWC：INT8 行跨度为 N 字节，INT32 为 N×4 字节。N=5/6/7 的输出可直接作为下一层卷积的输入，无需行补齐或重排。通用 GEMM 使用描述符中的显式 C stride；软件接口继续要求其4字节对齐且能容纳真实输出行。

## 融合池化边界

卷积→池化允许空间尾块，融合消费者只遍历有效行。窗口间隙、尾部未覆盖的真实像素仍进入原始输入缓存，物理补齐行不进入。融合池化仍要求 N 包含完整 COLS 通道组且为4通道组，尚无部分输入通道组的 lane mask。独立池化与残差 ADD 的原有通道/字节对齐约束没有改变。

FC→池化仍使用原来的单真实样本、完整物理 M tile 与完整通道组约束，坐标只在真实结果握手时推进。

## 验证入口

```bash
make tail-check
make regression
make fc-pool-check
make fusion-check
```

尾块专项包含：4/8列全部列余数，3/4/8行阵列全部行余数，16/24大小 K 块的全部非零余数；1×1×1、1001个逻辑输出、M=49卷积；INT32/INT8、偏置、逐通道参数、ReLU、普通/PSUM/B驻留路径；未对齐行、4KiB拆分、写响应延迟和错误；连续卷积、紧凑尾通道输入及池化真实像素计数。逐字节写入计数和邻接哨兵检查确保没有额外写入，读监视器检查没有读取无效矩阵行或参数。

这些是确定性整数功能测试。ResNet-50 的真实模型整网编译、量化、精度和吞吐验证仍未完成；本次不提供工艺时序或功耗结论。
