# ResNet50 卷积读取与调度优化消融

本实验用于给整网性能优化提供可复核数据。使用支持完整ResNet50的同一版RTL，分别关闭和开启卷积读缓存、片段前瞻及部分tile调度快路径，测量整网周期和DDR流量。两组都保留原生64位操作数读取；结果不包含从32位读取改为64位读取的贡献。

## 对照边界

共同源码固定为 `f7419986f24fb7a2ba9902eb5e451e147d6b7abc`。优化组保持该版本功能RTL字节不变；基线组只在隔离的仿真源码副本中应用以下关闭补丁，不修改工作区功能RTL：

| 优化 | 基线组 | 优化组 |
| --- | --- | --- |
| 卷积读缓存 | `CONV_CACHE_ENABLE=0`，直通读取 | 256行×64位，即2 KiB数据容量，另有tag/valid |
| 卷积片段前瞻 | 读完成后进入已有 `ST_PREP` | 在读完成时准备下一连续片段 |
| B驻留时下一N块的预取 | 等待当前驻留B释放 | 利用另一bank提前装载 |
| 计算bank快速获取 | 经已有 `CP_ACQUIRE` 状态 | tile就绪时在 `CP_IDLE` 提前申请，保留部分授权回退 |

基线仍保留其他已有双缓冲、A复用、部分和管理和通用预取，不代表所有预取都关闭。两组共同使用4×4 INT8阵列、INT32累加、K分块256、A/B各双bank、4个PSUM槽、AXI64读/AXI32写、读burst首拍等待20周期及额外B响应延迟0。不同命令之间继续通过DDR交接，没有增加跨层特征缓存。

旧 `46f756e`/`984c253` 缺少可配置补边MaxPool，以及M/N逻辑尾块的完整读取、参数和写回屏蔽，无法直接执行同一真实网络。因此本实验采用当前RTL的受控消融，不把旧版本的功能缺口算入性能收益。

## 网络与正确性

使用真实 `resnet50_v1.onnx` 权重，SHA256为 `358c5906f4057cfff3506a63bcf7b502e69e566bdaa9ea598466fe002c3bd3fa`。保持原224×224×3输入、全部残差分支及1001个输出，共72条命令：53个Conv、16个Add、1个带padding的独立MaxPool、1个GAP、1个FC。两组复用完全相同的29,404,672字节整数DDR部署包和描述符。

输入使用seed8的确定性非零INT8数据，激活固定scale为0.0625；包明确标记 `integer_performance`、`calibrated=false`、`accuracy_not_measured=true`。本实验验证整数执行和周期，不测分类精度。

独立NumPy整数参考保持不变，RTL在每条命令完成时核对完整输出，避免DDR地址复用覆盖旧层后漏检；最后核对完整部署映像。72层累计逻辑输出16,837,097字节，最终DDR期望SHA256为 `2c20633f1688bd23f1686548b8d1f4729b92a6863aa97f3cec1e056cf83e4f86`。两组都必须通过全部数值检查，才计算加速比。

## 整网实测结果

2026-10-26，两组完整RTL仿真均通过全部72层和完整29,404,672字节DDR检查，严格来源比较也通过。这里的“优化组”指原始四项功能全开的配置，不预设它一定更快。

| 指标 | 四项关闭的基线 | 四项开启的原配置 | 变化 |
| --- | ---: | ---: | ---: |
| 整网周期 | 489,351,345 | 503,021,224 | 增加13,669,879，慢2.79% |
| AXI读字节 | 1,278,406,224 | 1,158,799,696 | 减少119,606,528，降低9.36% |
| AR请求数 | 11,065,013 | 10,112,780 | 降低8.61% |
| 实际写字节 | 16,837,097 | 16,837,097 | 相同 |
| 有效MAC/周期 | 8.0683 | 7.8491 | 降低 |
| 端到端有效MAC利用率 | 50.4271% | 49.0568% | 降低1.3704个百分点 |

整网计数还包含逐层测量窗口外的30,025周期及9,216字节控制读取，两组相同；实际写字节等于全部层写入之和。

周期降低率为-2.793469%，加速比为0.972824倍。原配置的503,021,224周期、读写流量以及最终DDR哈希与此前整网结果一致。本次结果说明读取字节减少并不保证整网更快，不能写成“ResNet50加速2.79%”，也不能将ResNet8的历史收益套到本网络。

## 分层定位

| 卷积类型 | 层数 | 基线周期 | 原配置周期 | 周期变化 |
| --- | ---: | ---: | ---: | ---: |
| 7×7首层 | 1 | 41,144,525 | 33,500,589 | 降低18.58% |
| 3×3 | 16 | 171,992,997 | 168,533,781 | 降低2.01% |
| 1×1 | 36 | 192,204,131 | 216,979,170 | 增加12.89% |

1×1卷积多花24,775,039周期，超过7×7首层节省的7,643,936周期和3×3合计节省的3,459,216周期；FC另节省2,008周期，Add、MaxPool和GAP不变，合计正好多花13,669,879周期。

1×1中，13层B驻留任务由77,854,195变为98,853,369周期，多花20,999,174周期，而这组的读字节完全相同；17层多K A复用任务多花3,809,003周期，其余6层节省33,138周期。退化主要集中在1×1的B驻留组。四项功能在本实验中共同开关，分组计数只能定位问题范围，不能单独认定是缓存、片段前瞻或某一调度改动导致退化。若后续修改性能，应先做单项开关对照，再决定各类卷积的策略。

54条Conv/FC命令的运行窗口中，核心忙周期均为272,264,472；操作数路径忙而核心闲的周期由118,290,213增加到133,909,772，多15,619,559周期。运行窗口的核心/操作数活动分区已逐层核对。这进一步指向读取与调度过程的额外开销，但活动计数不能全部归因为DDR等待，也不能当作PE有效MAC数。

有效MAC统计排除卷积边界补零，为3,948,253,952；完整逻辑窗口MAC为4,089,186,304。端到端有效利用率使用前者除以16个PE和整网周期，均不因数值为零而扣减。实际写字节按每个已接收写拍的WSTRB计数，不能统一用写拍数乘4代替。

## 验证与证据

运行前通过38项模型工具测试（含8项补丁范围/原子性保护和10项消融运行器校验），关闭优化的隔离RTL也通过调度器、独立加载完成、卷积读取及逻辑尾块四项现有定向testbench。额外以新生成的未校准8层残差图验证整套流程：基线49,209周期、原配置30,394周期，两组所有层及完整7,296字节DDR均与独立整数参考一致；这些小图周期只验证工具，不作为ResNet50整网收益。

已提交的[精简实测记录](reference/resnet50_readpath_summary.json)保存整网、全部72层、按算子/卷积窗口/数据流分组的周期与流量，以及两组源码、精确补丁、黄金结果和完整日志哈希。完整本地产物位于 `build/resnet50-readpath-benchmark/`，包括 `baseline-report.json`、`optimized-report.json`、`comparison.json`、逐层CSV和两组RTL日志。`comparison.json` 的PASS表示比较条件和数值通过，不表示性能提升。

本次增加测试工具与测量记录，没有修改工作区功能RTL。简历可表述“完成真实ResNet50的72条任务整数执行与逐层/整网性能验证”；性能优化百分比仍须使用对应模型、对应条件的实测结果，分类精度另行验证。

## 复现

本地需要VCS、Python3和NumPy。首先通过已有入口准备真实模型包及黄金结果，再执行消融：

```bash
make resnet50-reference
make resnet50-readpath-benchmark DDR_RD_LATENCY=20 DDR_WR_LATENCY=0
```

若模型与黄金结果已经准备完成，只需第二条命令。消融入口不会重新量化模型或覆盖原黄金结果，只把必要参考文件按原字节复制到独立输出目录。原模型和参考目录可分别通过 `RESNET50_MODEL_DIR`、`RESNET50_CHECK_DIR` 指定，消融输出由 `RESNET50_READPATH_DIR` 指定，默认 `build/resnet50-readpath-benchmark/`。

报告保留源码原始/编译哈希、精确关闭补丁、开关条件、共同testbench、模型/输入、黄金结果、RTL日志及完整DDR哈希。比较器检查差异只出现在声明的三个RTL文件和四个受控优化开关中。
