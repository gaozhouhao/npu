# 全连接、形状转换与池化流式融合

当模型明确包含 `Fully Connected（全连接）→ Reshape（形状转换）→ MaxPool（最大池化）` 时，硬件可以将全连接的 INT8（8位整数）结果直接解释为 HWC（高度、宽度、通道）张量并送入池化，最终只写池化结果到 DDR（外存）。形状转换不改变数值和元素顺序。

模型必须明确给出 `(H,W,C)`；不能仅凭全连接的输出数量猜测。例如 192 个数可以表示多种形状，本实现不会自行选择其中一种。当前只支持一个真实样本、VALID（不补边）最大池化，且全连接结果已经过 INT8 再量化。激活函数仍按原顺序在池化之前执行。

## 元素如何变成空间坐标

全连接计算仍为 `A[1,K] × B[K,N]`，其中 `N=H*W*C`。硬件阵列要求完整计算块，因此描述符的 M 是阵列行数；只有第0行是真实样本，其余行由原全连接输入打包函数补齐，不参与池化输出。

对第0行的全连接输出编号 `j`，空间坐标为：

```text
channel = j % C
pixel   = j // C
y       = pixel // W
x       = pixel % W
```

上述公式定义逻辑排列。FC 坐标模块的数据通路通过计数器实现：`pixel_q`、`channel_q` 在复位和接受新命令时清零，`fc_pool_start` 用已校验的 C 初始化末通道起点 `C-COLS`。每次真实最终结果被池化成功接收，通道起点增加 COLS；到达末通道组后回到0，像素加1。反压、补齐物理行和中间 K 块不推进；窗口间隙或尾部的真实像素只要握手成功仍推进。COLS=8 时一次握手覆盖完整8通道，池化内部两个4通道组的处理不会额外推进坐标。卷积继续透传原坐标。

当前单个 M 计算块下，普通调度和多 K A 重用调度都按输出编号递增提交最终结果，结果快照保持该顺序。引擎的仿真断言逐次检查源输出编号等于累计接收的元素数，并按 COLS 累加，防止后续调度改动破坏这一前提。坐标转换中不再计算 `j/C` 或 `j%C`；启动配置和既有形状、容量及计数范围校验保留。

每个通道数 C 必须至少等于阵列列数 COLS，并能被 COLS 整除；COLS 至少为4且是4的倍数。这样一个计算块的输出不会跨越像素通道边界。后处理仍为加偏置、再量化、可选 ReLU（修正线性单元）；池化比较有符号 INT8 数值。

N 和 K 还受到硬件计算块计数器限制：`N/COLS <= 2^TILE_COUNT_WIDTH-1`，`ceil(K/K_TILE_SIZE) <= 2^TILE_COUNT_WIDTH-1`。默认计数器宽16位，因此最多65535个输出计算块或 K 计算块，65536会被拒绝。构建函数的 `tile_count_width` 默认16，`k_tile_size` 默认256；使用其它硬件配置时应显式传入对应值。K 分块大小必须为8的倍数，保证读取地址对齐。硬件向上取整加法先扩展到64位，软件按实际块计数检查溢出。H、W、C 及它们的乘积 N 必须是正的32位无符号整数，A/B行跨度按8字节对齐后也必须能用32位表示。

## 描述符与参数格式

命令继续占64字节，`opcode=1` 表示矩阵乘法，flags 的 bit7 表示本融合模式。words 10～12 保留原 A、B、C 行跨度；C 行跨度必须为未池化的 N。word 15 保留池化窗口、步长编码，低字节起依次为窗口高、窗口宽、纵向步长、横向步长；整字为0兼容2×2窗口、步长2。

参数区从原16字节头扩为32字节头，以下偏移均以字节为单位：

| 偏移 | 内容 |
|---:|---|
| +0 | 公共再量化乘数 M；逐通道模式填0 |
| +4 | 公共右移量 R；逐通道模式填0 |
| +8 | 输入零点，有符号32位编码 |
| +12 | 输出零点，有符号32位编码 |
| +16 | H |
| +20 | W |
| +24 | C |
| +28 | 真实样本数，必须为1 |
| +32 | 偏置或逐输出元素的参数记录起点 |

逐张量模式的记录为每个全连接输出一个 INT32（32位整数）偏置；逐通道模式为每个输出一个 `(bias,M,R)` 三字记录。这里的逐通道指全连接的 N 个输出，参数总数是 H×W×C，不能只提供 C 份参数。输入零点修正仍在软件中合入偏置，乘数、右移量及溢出检查复用原全连接参数打包逻辑。普通全连接和卷积继续使用原16字节头。

外存只分配 `pooled_H * pooled_W * C` 字节；不会写入其余补齐样本。描述符中 C 行跨度仍为 N，并不表示融合结果需要分配 `M*N` 字节。

## 软件入口与容量限制

当前缓存保存池化前的原始INT8输入，并与卷积共享窗口读取接口，结构和最新验证见[原始池化输入缓存](pooling_input_buffer.md)。

池化结果经默认16项的输出 FIFO 交给独立 DMA，顶层参数为 `POOL_OUTPUT_FIFO_DEPTH`。FC 的源结果在真实行全部成功交接后可退休；整层 `done` 仍等待窗口、归约、FIFO与最终写响应排空。输出地址与数据一起入队，后续FC坐标推进不会改变已排队结果。数值格式、描述符和原始行缓冲容量要求不变。

`compiler/fc_pool.py` 提供独立的纯标准库构建函数：

```python
from fc_layout import pack_fc_input, pack_fc_weights
from fc_pool import plan_fc_pool_layout, pack_fc_pool_params, make_fc_pool_descriptor

plan = plan_fc_pool_layout(k=9, reshape_shape=(4, 6, 8))
a_data = pack_fc_input(input_bytes, plan['fc_layout'], input_zero_point=-3)
b_data = pack_fc_weights(weight_bytes, plan['fc_layout'])
params = pack_fc_pool_params(weight_bytes, biases, plan,
                             input_zero_point=-3, output_zero_point=5,
                             requant=[(1, 0)]*192)
desc = make_fc_pool_descriptor(plan, a=4096, b=8192, c=12288, param=16384)
# 在最终输出地址分配 plan['c_bytes']，本例为48字节。
```

示例中参数必须来自模型量化配置；`(1,0)` 仅用于演示接口。调用者负责按 `a_bytes`、`b_bytes`、`c_bytes`、`param_bytes` 分配互不冲突的外存区域，并提供模型本身要求的形状。公共乘数模式使用 `per_channel=False`，参数打包时改传 `global_requant=(M,R)`。

输入和权重行跨度按8字节对齐，必须能用32位无符号整数表示。构建描述符时，各区域的起始地址和实际大小使用完整整数运算检查：起始地址不得为负、不得超过64位范围，最后一个有效字节不得超过 `2^64-1`。C 区域按实际池化后大小检查，参数区按扩展头和全部记录检查；调用者仍需保证这些区域实际映射到外存且互不冲突。

全连接和卷积共用池化前的原始 INT8 输入行缓冲。这里的原始数据指 Bias/Requant/ReLU 之后、池化计算之前的数据。最大值归约在窗口读取后进行，缓存不提前丢弃窗口样本；后续新增池化运算可复用相同原始窗口输入。本版全连接融合要求完整通道的 KH 行原始输入都能驻留片上：

```text
required_words = kernel_height * input_width * (C / 4)
required_words <= pool_line_words
```

该容量与池化步长无关。例如 H=4、W=6、C=8、KH=2 时需要24个32位字。即使一个 COLS 通道块能够放下，也不会自动采用卷积融合的通道分块遍历。容量不足、多个真实样本、补边或通道不齐时，构建函数直接拒绝，调用方应保留分开的算子执行。`target.validate_descriptor` 检查命令静态字段；H/W/C、样本数和完整状态容量由构建函数检查，因为这些值存放在参数区。

现有 MNIST 编译入口不自动生成本模式；SmallCNN 软件解释器明确拒绝这种命令，避免把扩展参数头或池化结果当普通全连接数据处理。模型接入应使用显式形状构建函数，并另行提供与该模型匹配的参考结果。卷积融合优化检查其它命令的参数读取范围时，已经计入新增16字节头，避免遗漏别名依赖。
