# FC 与卷积共用的原始池化输入缓存

需要池化的 FC 与卷积共用以下数据通路：

```text
Conv 结果 → 原坐标透传 ─┐
                       ├→ pool_window_buffer → 池化运算 → AXI 写回
FC 结果 → HWC 坐标适配 ─┘
```

`pool_window_buffer.sv` 保存后处理得到的原始 INT8 数据。每次输入握手原样写入一组 COLS 通道，不预先求最大值、求和或丢弃窗口外像素。FC 坐标仍只在真实结果成功握手时推进；补齐样本行和中间 K 块不进入缓存。COLS=8 时一次握手写入完整8通道。

缓存保留 KH 个完整输入行。某个有效窗口的右下角像素写入后，读取器按窗口内的行、列顺序重新读出原始样本，每次输出同一像素的4个相邻通道；一个4通道组的全部样本发完后，再处理下一个组。读取器完成当前窗口前暂停接收下一组输入，防止环形槽位提前覆盖。

窗口输出接口与具体池化运算无关：

| 信号 | 含义 |
|---|---|
| `sample_valid / sample_ready` | 原始窗口样本的接收握手 |
| `sample_data[31:0]` | 4个未经归约的 INT8 样本 |
| `sample_first / sample_last` | 当前4通道窗口的第一个、最后一个空间样本 |
| `sample_spatial_index` | 池化输出像素编号 |
| `sample_channel_base` | 当前4通道组的全局通道起点 |

反压期间这些信号保持稳定。`pool_max_reducer.sv` 是目前接入的运算模块，逐样本计算有符号最大值。原有 `stream_maxpool2x2.sv` 名称和外部命令、输入、AXI 接口保留，由它连接原始缓存、最大值运算和写回。后续可在窗口接口接入平均值、最小值或其它池化运算；本次没有新增这些运算的描述符编码或选择开关。

容量按32位字计算：

```text
全通道：KH × input_W × (C / 4)
单个通道块：KH × input_W × (COLS / 4)
```

`LINE_WORDS` 表示原始输入缓存的物理容量。全通道容纳时，不同通道块的空间扫描可交错，各通道块内部仍按光栅顺序前进。卷积在全通道容量不足、单块容量满足时，可完成一个通道块的全图后复用缓存。FC 按像素交错发送通道组，因此仍要求全通道容量满足。单块也放不下的卷积和全量放不下的 FC 会被软件及硬件容量检查拒绝。

环形缓存地址包含输入行、列和通道块，原始 SRAM 不在每次启动时整体清零。新任务的窗口必须在所有样本已写入后才能读出；仿真专用标签检查任务代次、像素与通道是否匹配，以发现未写入或被提前覆盖的数据。标签不进入综合硬件。

这一结构增加了原始数据容量和窗口重读工作量。旧的部分最大值缓存容量、周期测量不能直接套用；最高频率和实际吞吐量仍需另行测量。
